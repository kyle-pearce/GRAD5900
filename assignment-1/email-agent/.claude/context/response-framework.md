# Response Framework

Structural how-to guide for email drafting. This file contains no personal data —
it defines the composition pattern the agent should follow.

---

## Opening Line

Always reference the sender's email directly. Never use generic openers.

**Good patterns:**
- "Thanks for your message about [topic]."
- "I wanted to follow up on [specific item from their email]."
- "Appreciate you reaching out re: [subject]."
- "Thanks for the update on [project/topic]."

**Avoid:**
- "Hope this email finds you well."
- "I hope you're having a great day."
- Generic "Hi [Name]," with no acknowledgment of their message.

---

## Body Structure

### For simple replies (1-2 paragraphs)

1. **Acknowledge** — briefly restate what they asked or shared
2. **Respond** — give the answer, decision, or action
3. **Next step** — one clear sentence on what happens next

### For complex or multi-part replies

Use bullet points or numbered lists when:
- Answering multiple distinct questions
- Providing step-by-step instructions
- Listing action items with owners

Keep prose to topic sentences + supporting detail. No walls of text.

### For ambiguous emails

If the ask is unclear, do NOT guess. Instead, include a single clarifying question:
> "Before I respond fully — could you clarify [specific ambiguous point]?"

One question only. Asking multiple questions in one email is hard to parse.

---

## Closing

Every email should end with a clear next step or call-to-action:

- **If action is on them:** "Let me know your thoughts by [timeframe if applicable]."
- **If action is on you:** "I'll have [deliverable] to you by [date/timeframe]."
- **If no action needed:** "Happy to discuss further if helpful."
- **For meeting requests:** "I'm free [day/time options]. Does any of those work?"

---

## When to Use Bullet Lists vs Prose

| Use bullets when... | Use prose when... |
|---------------------|------------------|
| 3+ distinct points | 1-2 related points |
| Step-by-step instructions | Conversational replies |
| Action items with owners | Brief acknowledgments |
| Comparing options | Expressing a single decision |
| Multi-part questions | Quick follow-ups |

---

## Length Guidelines

| Email type | Target length |
|------------|--------------|
| Quick acknowledgment | 1-3 sentences |
| Standard reply | 3-5 sentences / short paragraph |
| Multi-part response | 2-3 paragraphs or structured list |
| Complex technical response | Up to 4 paragraphs with headers if needed |

Ruthlessly cut anything that doesn't serve the recipient's need.

---

## Handling Specific Scenarios

### Meeting requests
- Confirm or decline clearly
- If confirming: propose 2-3 time slots
- If declining: offer an alternative (different time, async option)
- Always include what you'll prepare/bring if applicable

### Follow-up / nudge emails
- Lead with the specific thing you're following up on
- State the impact or deadline if relevant
- One clear ask: "Could you [action] by [date]?"

### Deliverable updates
- Lead with status: on track / delayed / complete
- If delayed: state new timeline and reason briefly
- Close with what help (if any) you need

### Feedback / review requests
- Thank them for taking the time
- Make the ask specific: "Would you focus on [section/aspect]?"
- Give a deadline if you have one
